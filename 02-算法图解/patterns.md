# 模式与框架库

本书作者反复使用的思考框架、决策规则与反模式。

## 框架 1：算法选型决策树（作者全书骨架）

```
拿到一个问题 →
  是"查找"吗？
    ├─ 数据有序？ → 二分查找 O(log n)
    └─ 无序？ → 简单查找 O(n) 或先排序
  是"排序"吗？
    └─ 数据量大 → 快速排序 O(n log n)；小规模才用选择排序
  是"映射/查重/缓存"吗？
    └─ 散列表 O(1)
  是"网络里找路"吗？
    ├─ 边没权重 → BFS（段数最少）
    └─ 边有权重 → 狄克斯特拉（总权重最小）；有负权 → 贝尔曼-福德
  是"约束下求最优"吗？
    ├─ 子问题可独立拆分 → 动态规划（精确最优）
    └─ 子问题互依赖 / 要快 → 贪婪近似
  是"预测/分类新东西"吗？
    └─ KNN：抽特征 → 找最近 K 个邻居
```

## 框架 2：D&C 两问（分而治之）

遇到递归类问题，先问：
1. 基线条件是什么？（简单到不用分解的情况；数组题通常是空/单元素数组）
2. 每次怎么把问题缩小一圈？（去掉第一个元素 / 划掉一半 / 分成两个小同款问题）

## 框架 3：大O三问（判断运行时间）

1. 输入规模 n 是什么？
2. 每一步操作多少次？（打印所有元素 = O(n)；每个元素乘所有元素 = O(n²)）
3. 常数忽略，最糟情况兜底。

## 框架 4：NP 完全识别清单（原书 8.4.2）

蛛丝马迹，命中多个就该警觉：
- 元素少时很快，n 一大就慢得离谱；
- 涉及"所有组合/所有排列"；
- 不能拆成独立小问题；
- 涉及序列（城市顺序）或集合（广播台集合）；
- 能归约成旅行商或集合覆盖问题。

→ 应对：**别找精确解，直接设计贪婪近似算法**。

## 决策规则（if/else 速查）

- **if 需要随机读取** → 用数组；**else if 频繁中间插删** → 用链表。
- **if 列表有序** → 二分查找；**else** → 简单查找或先排序。
- **if 要"名字→数据"的快速映射** → 散列表。
- **if 边有权重** → 狄克斯特拉；**else if 边无权重** → BFS。
- **if 有负权边** → 不用狄克斯特拉，换贝尔曼-福德。
- **if 子问题独立可拆分** → 动态规划；**else** → 贪婪近似或别的思路。
- **if 新样本要分类/预测数值** → KNN（先把特征选好）。

## 反模式（作者明确反对的做法）

1. **在 n 还小的时候就下结论"这算法够快"**
   - 例子：Bob 用 100 元素时的 15 倍差距推断火箭算法；实际 10 亿元素时差 3300 万倍。
   - 替代：看大O曲线形状，不看当前耗时。

2. **已排序数组 + 每次插入后重排**
   - 问题：为了二分查找，每次新用户注册都把数组整体排序。
   - 替代：用二叉查找树（第11章）或散列表。

3. **在 NP 完全问题上死磕精确解**
   - 问题：试遍 2ⁿ 个子集、n! 条路线。
   - 替代：贪婪近似，速度快且接近最优。

4. **递归不写基线条件**
   - 后果：无限递归 → 栈溢出。
   - 替代：每个递归函数先写"什么时候不再调自己"。

5. **BFS 不标记已检查节点**
   - 后果：同一节点入队两次，甚至在"你↔Peggy"间无限循环。
   - 替代：维护 searched 名单。

6. **用狄克斯特拉处理负权边**
   - 后果：得到错误路径。
   - 替代：贝尔曼-福德。

7. **KNN 随便挑特征**
   - 后果：给小猫图片打分来推电影，推荐全偏。
   - 替代：特征必须与目标相关、不偏不倚。
