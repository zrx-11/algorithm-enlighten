# 第 5 章：散列表

- **难度**：★★☆ | **预估学时**：2 小时 | **前置**：第 1、2 章（数组）

## 学习目标

学完本章，你能：

1. 解释散列表 = 散列函数 + 数组，并说出散列函数的两个要求。
2. 说出散列表三大用途（映射、防重复、缓存）并各举一个原书例子。

## 一句话核心

**散列表是"给个商品名立刻报出价格"的魔法店员：散列函数把键算成一个数组下标，让查找、插入、删除平均都只要 O(1)——代价是设计不好会撞位置（冲突），要靠好的散列函数和低填装因子避开。**

## 零基础讲解

### 概念 1：散列函数与散列表（难度：基础）

**散列函数（hash function）**：给它任意数据，它还你一个数字。两个要求：

1. **一致性**：同样的输入永远得到同样的输出（输入 apple 永远得 4）。
2. **均匀性**：不同输入尽量映射到不同位置。

**散列表（hash table）= 散列函数 + 数组**。查价格时不用翻本子，直接把商品名喂给散列函数，它给出下标，一步取到价格。Python 里的 **字典（dict）** 就是散列表：

```python
book = {}                    # 等价于 book = dict()
book["apple"] = 0.67         # 键: 商品名; 值: 价格
book["milk"] = 1.49
book["avocado"] = 1.49
print(book["avocado"])       # => 1.49，一步拿到
```

### 概念 2：三大用途（难度：基础）

1. **模拟映射关系**：电话簿（姓名→号码）、DNS 解析（网址→IP 地址）。
2. **防止重复**：投票站查重。
   ```python
   voted = {}
   def check_voter(name):
       if voted.get(name):      # get 找不到时返回 None
           print("kick them out!")
       else:
           voted[name] = True
           print("let them vote!")
   ```
3. **做缓存**：网站把主页存进散列表，下次同一 URL 直接返回，不再重新计算。
   ```python
   cache = {}
   def get_page(url):
       if url in cache:
           return cache[url]
       data = get_data_from_server(url)
       cache[url] = data
       return data
   ```

### 概念 3：冲突、填装因子、性能（难度：进阶）

**冲突（collision）**：两个不同的键被散列函数算到了同一个数组位置。解决办法：该位置挂一条**链表**（拉链法）。如果散列函数很烂、所有键挤在同一个位置，散列表就退化成一条长链表——O(1) 变 O(n)。

**填装因子（load factor）= 已被占用的位置数 ÷ 数组总位置数**。

- 因子越低越空、冲突越少。
- 原书经验法则：**填装因子超过 0.7 就扩容（通常数组翻倍，再重新散列所有元素）**。
- 扩容虽贵，但均摊下来散列表操作仍是 O(1)。

**性能结论（原书）**：

| | 平均情况 | 最糟情况 |
|---|---|---|
| 查找/插入/删除 | O(1) | O(n)（全撞车） |

避开最糟的两件事：**好的散列函数 + 保持低填装因子**。

## 类比与实例

- **类比**：散列表 = 超市里过目不忘的店员 Maggie。不管货架上多少商品，问她"苹果多少钱"她立刻答——O(1)。数组+散列函数就是你雇到 Maggie 的方式。
  - 失效边界：如果 Maggie 记忆力差（烂散列函数），问 A 商品她跑去 B 商品的位置乱答，或者把所有答案堆在一个格子里，她就得逐个翻——魔法失效。
- **实例（可复核）**：长度为 10 的数组已放 3 个元素 → 填装因子 3/10 = 0.3，很安全；放 8 个 → 0.8，超过 0.7 红线，该扩容到 20 格再重散列。

## 常见误解

- **别以为"散列表最糟也是 O(1)"**——实际上全冲突时就是 O(n)；必须靠好散列函数 + 低填装因子保住平均 O(1)。
- **别以为"散列函数把不同输入映射到不同位置"真能做到**——实际上几乎不可能，冲突必然发生，所以才需要拉链法和扩容机制。
- **别以为"扩容很贵所以不要扩容"**——实际上扩容后填装因子骤降，均摊下来每次操作仍是 O(1)；不扩容才会被冲突拖垮。

## 自测题（答案）

1. （单选）平均情况下，散列表查找一个键的时间是？A. O(log n)　B. O(n)　C. O(1)　D. O(n²)
   （答案：C；解析：不管散列表多大，散列函数一步定位下标。）
2. （单选）投票站要快速判断"这个人投过没有"，最适合用？A. 数组　B. 链表　C. 散列表　D. 栈
   （答案：C；解析：原书 5.2.2——列表查重是 O(n)，散列表 get 一下就知道。）
3. （填空）原书经验法则：填装因子超过 ____ 时就该给散列表扩容。
   （答案：0.7；解析：超过后冲突概率明显上升，扩容后因子骤降。）
4. （简答）两个键撞到同一个位置（冲突）会怎样？最简单的处理办法是什么？
   （答案：该位置挂一条链表，把两个键都存在链表里；查询时要在短链表中找一下。链表越短越快，所以散列函数要把键均匀铺开。）

## 复习锚点

- 散列表 = 散列函数 + 数组；Python 的 dict 就是它。
- 用途：映射、防重复、缓存。
- 平均 O(1)、最糟 O(n)；靠好散列函数 + 填装因子 < 0.7 维持性能。
