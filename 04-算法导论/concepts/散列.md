# 散列

- **难度**：基础 | **涉及章节**：第 11 章

## 一句话定义
**用散列函数 h(key) 把 key 直接映射到数组下标，让「查找/插入/删除」平均 O(1)——代价是要处理「不同 key 撞到同一槽」（碰撞）。**

## 为什么重要
散列表是所有「键值存储」的底座：Python dict、Java HashMap、数据库的内存索引。理解「平均 O(1) 是怎么来的、什么情况下会退化」是数据结构的基本功。

## 图示
```mermaid
flowchart TD
    A[key] --> B[散列函数 h(key)]
    B --> C[数组槽 h(key)]
    C --> D{槽里空吗?}
    D -->|空| E[直接放入]
    D -->|碰撞| F{怎么处理碰撞?}
    F -->|链表| G[拉链法: 槽挂链表]
    F -->|线性探测| H[开放寻址: 找下一个空槽]
    G --> I[完全散列: 二层无碰撞, 查询最坏 O(1)]
```
**看图说明**：散列的核心矛盾是「h 把大 key 空间压到小数组」；碰撞处理决定常数与最坏情况。

## 详解
- **直接寻址**：key 就是下标。要求 key 范围小。
- **散列表**：用 h(key)∈[0,m) 压缩。装载因子 α=n/m。
- **碰撞处理**：
  - **拉链法**：每个槽挂链表；期望查找 O(1+α)。
  - **开放寻址**：线性/二次/双重散列找下一个空槽；不挂链表。
- **散列函数**：除法散列 h(k)=k mod m；乘法散列 h(k)=⌊m(kA mod 1)⌋；全域散列用随机函数族防恶意输入。
- **完全散列**：二层结构，最坏 O(1) 查询。

类比：散列表像「按手机号尾号分抽屉」——尾号相同的人放同一抽屉（碰撞），抽屉里挂个名单（拉链法）。失效边界：若所有 key 都撞到同一槽，退化成链表 O(n)；全域散列就是防这种恶意。

## 常见误解
- 别以为「散列表最坏 O(1)」——实际上最坏是 O(n)（全碰撞），O(1) 是期望。
- 别以为「开放寻址就是删元素时直接清空」——实际上删除要打「墓碑」，否则探测链断了。
