# 摊还分析

- **难度**：进阶 | **涉及章节**：第 10、17、19 章

## 一句话定义
**一整个操作序列的总成本除以操作数，得到「每次的平均代价」——哪怕单次最坏很贵，只要均摊下来便宜就算便宜。**

## 为什么重要
动态表扩张、斐波那契堆的「减小键值」、栈的「多弹」这些操作单次看很贵，但反复用下来平均很便宜。摊还分析告诉你「真实平均成本是多少」，而不是被最坏单次吓到。

## 图示
```mermaid
flowchart TD
    A[摊还分析三种方法] --> B[聚合分析: 算 n 次总代价 T(n), 每次=T(n)/n]
    A --> C[核算法: 给每种操作预收信用, 余额不能负]
    A --> D[势能法: 定义势能 Φ, 每次摊还代价=实际+ΔΦ]
    B --> E[动态表扩张: 总 O(n), 每次均摊 O(1)]
```
**看图说明**：三种方法殊途同归——聚合直接算总账，核算法像「预付充值」，势能法像「给数据结构记一本势能账」。

## 详解
- **聚合分析**：直接算 n 次操作总代价 T(n)，每次摊还 = T(n)/n。例：动态表从 1 开始翻倍扩张，n 次插入总代价 O(n) ⇒ 每次 O(1)。
- **核算法**：给便宜操作「多收一点」，存成信用留给贵操作用；全程信用不能为负。
- **势能法**：定义数据结构的「势能」Φ（如动态表中已用与容量差），每次操作摊还代价 = 实际代价 + Φ(后)−Φ(前)。

类比：动态表像「搬家」——每次箱子满了就买大一倍的箱子、把东西全搬一次（贵）；但因为箱子翻倍，两次大搬家之间要插很多次，平均下来每次插入几乎免费。失效边界：摊还分析只保证「序列平均便宜」，不保证「任意单次快」。

## 常见误解
- 别以为「摊还 O(1) 就是每次都 O(1)」——实际上单次仍可能 Θ(n)，只是均摊后便宜。
- 别以为「势能法要找物理势能」——实际上 Φ 是人为定义的账，选得合适就行。
