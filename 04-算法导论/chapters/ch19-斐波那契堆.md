# 第 19 章：斐波那契堆

- **难度**：★★★ | **预估学时**：2.5 小时 | **前置**：第 6、17 章

## 学习目标
学完本章，你能：
1. 说出斐波那契堆支持的可合并堆操作，以及哪些操作是摊还 O(1)。
2. 解释为什么它在 Dijkstra/Prim 这类「频繁 DECREASE-KEY」的图算法里比二叉堆好。
3. 理解「懒合并 + 势能摊还」的核心思想（不要求手写全部细节）。

## 一句话核心
**斐波那契堆把 INSERT/UNION/DECREASE-KEY 都做成摊还 O(1)——靠的是「先懒着不整理，等 EXTRACT-MIN 时才一次收拢」。**

## 零基础讲解

### 概念 1：可合并堆（mergeable heap）操作（书页 §19 已核对）
支持（以最小堆为例）：
- MAKE-HEAP、INSERT(H, x)、MINIMUM(H)。
- EXTRACT-MIN(H)：删最小并返回。
- **UNION(H₁, H₂)**：合并两堆。
- DECREASE-KEY(H, x, k)：减小 x 的关键字。
- DELETE(H, x)。

### 概念 2：与二叉堆对比（书页图 19-1 表格）
| 操作 | 二叉堆（最坏） | 斐波那契堆（摊还） |
|---|---|---|
| INSERT | Θ(lg n) | Θ(1) |
| MINIMUM | Θ(1) | Θ(1) |
| EXTRACT-MIN | Θ(lg n) | O(lg n) |
| UNION | Θ(n) | Θ(1) |
| DECREASE-KEY | Θ(lg n) | Θ(1) |
| DELETE | Θ(lg n) | O(lg n) |

关键：斐波那契堆把 INSERT/UNION/DECREASE-KEY 做到摊还 O(1)——这正是 Dijkstra/Prim 里「每条边松弛都 DECREASE-KEY」最想要的。

### 概念 3：结构直觉（难度：高难，了解）
- 斐波那契堆是一组**堆有序的树**组成的「森林」，用根链表串起来。
- **懒策略**：INSERT 就把新结点挂到根链表（O(1)，不整理）；UNION 就把两个根链表接起来（O(1)）；DECREASE-KEY 就把减小的子树切出来挂到根链表（O(1)）。
- **只有 EXTRACT-MIN 才整理**：从根链表找最小删之，然后把它的孩子们并入根链表，再「合并同度数的树」直到没有两棵树同度数——这一步才花 O(lg n) 摊还。
- 摊还分析用势能法（第 17 章）证明「懒攒下来的乱」被 EXTRACT-MIN 一次性付清。

### 概念 4：为什么叫「斐波那契」（了解）
分析中出现：某结点的孩子数最少时，其子树规模按斐波那契数增长——由此推出「一棵度数为 k 的树至少有 F_{k+2} 个结点」，所以度数 k = O(lg n)。

## 图示
```mermaid
flowchart LR
    A[INSERT / UNION / DECREASE-KEY] -->|懒: 直接挂根链表| B[森林越来越乱]
    B --> C[EXTRACT-MIN: 找最小, 删, 整理同度数树]
    C -->|摊还 O lg n| D[森林重新变整齐]
```
**看图说明**：平时「懒」是为了省时间（摊还 O(1)）；攒下来的乱在 EXTRACT-MIN 时一次性清算。

## 类比与实例
- **类比**：斐波那契堆像「洗衣篓策略」——平时脏衣服随手扔篓里（INSERT/UNION O(1)），只有「必须穿干净衬衫」（EXTRACT-MIN）时才一次性全部洗。**失效边界**：如果 EXTRACT-MIN 调用极其频繁，懒攒的优势就不明显；它最适合「插入多、删少」的场景。
- **实例**：Dijkstra 最短路：每条边 (u,v) 松弛时若 d(v) 能更小，就 DECREASE-KEY。二叉堆每条要 O(lg n)；斐波那契堆摊还 O(1)——稠密图上把总复杂度从 O(m lg n) 降到 O(m + n lg n)。

## 常见误解
- **别以为「斐波那契堆全面碾压二叉堆」**——实际上它常数大、实现复杂，工程里多数用二叉堆/四叉堆；它的价值在理论分析（Dijkstra 稠密图最优界）。
- **别以为「INSERT 在斐波那契堆里也要 O(lg n)」**——实际上摊还 Θ(1)，直接挂根链表即可。
- **别以为「DECREASE-KEY 是免费的」**——它摊还 O(1) 是靠 EXTRACT-MIN 时一次性清算攒下的乱，不是真的零成本。

## 自测题（答案）
1. （多选）下列哪些操作在斐波那契堆中是摊还 O(1)？（答案：A、B、C；解析：INSERT/UNION/DECREASE-KEY 摊还 O(1)；EXTRACT-MIN 是 O(lg n)）
   - A. INSERT   B. UNION   C. DECREASE-KEY   D. EXTRACT-MIN
2. （单选）斐波那契堆最适合下列哪种场景？（答案：C；解析：频繁 DECREASE-KEY 的图算法）
   - A. 纯排序   B. 频繁 EXTRACT-MIN   C. Dijkstra/Prim 频繁松弛   D. 纯栈操作
3. （填空）EXTRACT-MIN 时要把同__的树合并到只剩一棵。（答案：度数；解析：consolidate 按 degree 合并）
4. （简答）为什么 Dijkstra 用斐波那契堆比二叉堆快？（答案：Dijkstra 每条边松弛都可能 DECREASE-KEY；二叉堆每次 O(lg n)，总 O(m lg n)；斐波那契堆 DECREASE-KEY 摊还 O(1)，总 O(m + n lg n)，稠密图上优势明显）

## 复习锚点
- 可合并堆：INSERT/UNION/DECREASE-KEY 摊还 O(1)。
- 懒合并：平时挂根链表，EXTRACT-MIN 才整理。
- 核心用途：Dijkstra/Prim 图算法的理论最优界。
