# 第 18 章：B 树

- **难度**：★★☆ | **预估学时**：2 小时 | **前置**：第 13 章

## 学习目标
学完本章，你能：
1. 说出 B 树与红黑树的本质区别（多叉 vs 二叉、面向磁盘）。
2. 解释为什么数据库索引用 B 树而不是红黑树。
3. 描述 B 树查找、插入的大致流程与高度界。

## 一句话核心
**B 树是「一个结点挂很多孩子」的平衡搜索树——为磁盘设计：每次 I/O 读一大块，树高就压到极低。**

## 零基础讲解

### 概念 1：为什么需要 B 树（难度：基础）
书页 §18：红黑树适合主存（随机访问极快）。但**磁盘（辅助存储）**慢得多——一次寻道比主存访问慢上万倍，且磁盘是**按块读写**的（一次读一整个扇区/页）。
B 树的对策：让一个结点 = 一个磁盘块，块里塞很多关键字。这样树的「分支因子」（每个结点的孩子数）可以是几百到几千——树高极低（log_{几百} n），I/O 次数极少。

### 概念 2：B 树结构（难度：进阶）
- 内部结点 x 含 x.n 个关键字，有 x.n+1 个孩子。
- 关键字是「分隔点」：把 x 管的范围切成 x.n+1 个子域。
- 所有叶结点在同一深度（完美平衡）。
- 查找：在结点的 x.n 个关键字里做线性（或二分）比较，选出下一个孩子——一次磁盘 I/O 降一层。

### 概念 3：高度界（难度：进阶）
书页定理：含 n 个关键字、最小度数 t 的 B 树，高度 h ≤ log_t((n+1)/2)。虽然渐近仍是 O(log n)，但**对数的底 t 可以非常大**（几百），所以实际树高只有三四层——这对磁盘 I/O 是决定性优势。

### 概念 4：插入与删除（了解）
- 插入：沿查找路径往下，叶结点有空就放进去；满了就**分裂**成两个、中间关键字升进父结点（可能连锁分裂）。
- 删除：类似地可能引起**合并**。
所有操作沿一条根到叶路径，O(log_t n) 次 I/O。

**看图说明**：B 树不是为了在主存里比红黑树快，而是为了把「昂贵的磁盘 I/O 次数」从几十次压到三四次。

## 类比与实例
- **类比**：红黑树像逐页翻字典；B 树像先翻到「部首目录」（一大块塞几十个部首）、再翻「正文分区」——一次翻一大块，翻的次数极少。**失效边界**：在主存里 B 树单结点线性扫描几百个关键字反而比红黑树的二分慢——它的优势只在「磁盘读取代价 >> 内存比较代价」时才体现。
- **实例**：数据库索引（MySQL InnoDB 的 B+ 树）：一页 16KB 塞几百个索引项，千万级表只需 3~4 层，一次查询读 3~4 次磁盘。

## 常见误解
- **别以为「B 树就是红黑树的多叉版」**——实际上它是为磁盘块设计的；主存里红黑树/跳表常更合适。
- **别以为「B 树插入不会分裂」**——实际上叶满了要分裂、中间关键字上升，可能一路裂到根。
- **别以为「B 树与 B+ 树是一回事」**——B+ 树是 B 树变种：所有数据都在叶结点、叶串成链表，是数据库主流。

## 复习锚点
- B 树 = 多叉平衡搜索树，为磁盘块设计。
- 结点塞几百关键字 ⇒ 分支因子大 ⇒ 树高 log_t n 极低。
- 插入可能分裂、删除可能合并，沿根到叶一条路径。
