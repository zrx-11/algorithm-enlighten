# 模式与框架库

## 框架：实现 → 分析 → 比较 → 改进
本书作者的主循环。学任何算法都走这四步：先写 Java 实现，再用增长数量级分析成本，再和同类算法比较，再换数据结构改进。**何时用**：学新算法时照此流水线，不要背结论。

## 框架：分治（Divide & Conquer）
劈成两半 → 递归解决 → 合并。代表：归并排序、快排（切分）。**何时用**：问题能天然拆成独立子问题时。

## 框架：贪心（Greedy）
每一步选当前最优，不回头。代表：Prim（选最近横切边）、Kruskal（按边权从小到大）、霍夫曼（合并最小权）。**何时用**：局部最优能导出全局最优（需定理保证，如切分定理）。

## 框架：松弛（Relaxation）
反复"发现更短就更新"。代表：Dijkstra、最短路径树。**何时用**：求最优路径/距离类问题。

## 决策规则：选排序算法
```
需要稳定? ──是──> 归并排序
   │否
需要最坏 O(N log N) 保证且省内存? ──是──> 堆排序
   │否
通用最快? ──> 三向快排
近乎有序? ──> 插入排序
```

## 决策规则：选符号表实现
```
需要有序操作(min/floor/rank/范围)? ──是──> 红黑树 TreeMap
   │否
只要 put/get 求最快? ──> 散列表 HashMap
键是稠密整数? ──> 直接数组
```

## 决策规则：求图最短路
```
边权非负? ──是──> Dijkstra (E log V)
   │否
是 DAG? ──是──> 拓扑序松弛 (线性)
   │否
含负权? ──> Bellman-Ford
```

## 反模式
- **反模式：凭"感觉快"选算法**——作者反复强调要用倍率实验测成本，不凭直觉。
- **反模式：忽视最坏情况**——快排最坏 O(N²)，不随机化就埋雷。
- **反模式：在无序数组上用二分查找**——前提已排序，否则全错。
- **反模式：散列表不控制装载因子**——α→1 时探测链爆炸，退化成 O(N)。
- **反模式：把 BST 当有序数组用**——BST 最坏会退化，动态有序集合用红黑树。
