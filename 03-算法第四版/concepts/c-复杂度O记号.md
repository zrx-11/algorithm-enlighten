# 复杂度记号（O / ~ / 增长数量级）

- **难度**：基础 | **涉及章节**：第 1.4 节，贯穿全书

## 一句话定义
用"忽略常数和低阶项的函数类别"描述算法随输入规模 N 变大的快慢趋势，而不是具体毫秒数。

## 为什么重要
它是全书比较算法的**通用语言**。没有它，"快排和归并谁快"只能靠跑程序碰运气；有了它，一眼看出 N=百万时谁能跑完。

## 图示
```mermaid
flowchart LR
    A["1 常数"] --> B["log N 对数"]
    B --> C["N 线性"]
    C --> D["N log N"]
    D --> E["N² 平方"]
    E --> F["N³ 立方"]
    F --> G["2^N 指数"]
```
**看图说明**：越靠左越"扛得住大 N"。从 N 到 N² 是质变——10 倍输入从 10 倍慢变 100 倍慢。

## 详解
- **O(f(N))**：上界——运行时间不超过 f(N) 的常数倍。
- **~f(N)**：渐近等于——忽略低阶项，如 ~N²/2 与 ~N² 同级。
- 原书七兄弟：1 / log N / N / N log N / N² / N³ / 2^N。
- **类比**：判断烧水时间不看火苗大小（硬件常数），看"米量翻倍要多久"（倍率）。*失效边界*：N 很小时常数项主导，复杂度比较失灵。

## 常见误解
- 别以为 O(N²) 一定比 O(N log N) 慢——小 N 时带大常数的后者可能更慢。
- 别以为大 O 是精确时间——它只描述增长趋势。
