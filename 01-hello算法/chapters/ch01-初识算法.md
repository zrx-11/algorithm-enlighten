# 第 1 章：初识算法

- **难度**：★☆☆ | **预估学时**：1 小时 | **前置**：第 0 章

## 学习目标
学完本章，你能：
- 用自己的话说出"算法"是什么；
- 识别出生活中处处存在的算法；
- 看懂书中用斐波那契数列引出的"为什么要学算法"。

## 一句话核心
算法就是"解决一个特定问题的、一系列清晰可执行的操作步骤"。

## 零基础讲解
### 概念 1：算法（algorithm）（难度：基础）
**算法**是解决一个特定问题的有限操作序列：给你输入，它按固定步骤执行，最后给出输出。一个合格的算法要满足：有明确的输入输出、每一步含义清晰、步骤有限不会无限转下去。

注意：算法不只是"代码里的东西"。你每天做的很多事本身就是算法：

- **泡方便面**：烧水 → 放料 → 等 3 分钟 → 开吃。每一步有先后顺序。
- **导航 App**：从你出发，一步一步算到目的地的路线。

### 概念 2：本书的贯穿例子——斐波那契数列（难度：基础）
**斐波那契数列**：1, 1, 2, 3, 5, 8, 13, … 从第 3 项起，每一项等于前两项之和。求第 n 项 F(n)：

```python
def fib(n):
    if n == 1 or n == 2:
        return 1
    return fib(n - 1) + fib(n - 2)
```

这个递归写法虽然短，但当 n 变大时会慢得离谱（后面会讲：它是指数级 O(2ⁿ)）。这个例子在第 2 章会被反复拿出来对比——同一个问题，写法不同，效率天差地别。这就是"初识算法"要种下的第一颗种子。

### 概念 3：为什么算法无处不在（难度：基础）
搜索推荐、外卖派单、地图导航、人脸识别……背后都是"在海量数据里按某种规则快速找出最优解"的问题。算法的本质作用是：**用更少的步骤，得到正确的答案**。

## 图示
```mermaid

    In[输入] --> S1[步骤1] --> S2[步骤2] --> S3[步骤N] --> Out[输出]
```
**看图说明**：算法的通用形态就是一条"输入 → 一串明确步骤 → 输出"的流水线。判断它是不是好算法，就看两件事：结果对不对、步骤多不多。

## 类比与实例
- 类比：算法像菜谱。食材是输入，步骤是算法，端上桌的菜是输出。**失效边界**：菜谱可以"加盐少许"这种模糊描述，计算机算法必须每一步精确到可执行。
- 实例：找"从家到学校怎么走"——你可以先走遍每条路再挑最短（暴力），也可以只沿大路估算（启发式）。选择哪种"步骤序列"，就是在选择算法。

## 常见误解
- 别以为算法是数学家的专利——实际上它就是"做事的固定步骤"，你每天都在执行各种算法。
- 别以为"能算出答案的就是好算法"——实际上同一个斐波那契问题，递归版 n=50 时要算几小时，递推版几毫秒就出答案。算法的优劣体现在效率上。

## 自测题（答案）
1. （单选）下列哪项最符合本书对算法的定义？ A. 一段能跑的代码 B. 解决特定问题的一系列清晰可执行的操作步骤 C. 一个数学公式 D. 一个软件界面（答案：B；解析：算法强调"输入→有限步骤→输出"，代码只是它的一种实现载体。）
2. （填空）斐波那契数列中，F(n) = ______（用前两项表示）。（答案：F(n-1) + F(n-2)；解析：从第 3 项起，每一项等于前两项之和。）
3. （判断）一个算法只要能得到正确答案，就是好算法。（答案：错误；解析：好算法还要看效率（时间/空间开销），这正是第 2 章的主题。）

## 复习锚点
- 算法 = 解决特定问题的有限清晰步骤序列。
- 同一个问题可以有多个算法，优劣看效率。
- 斐波那契递归例子预告了"指数级慢"的问题。
