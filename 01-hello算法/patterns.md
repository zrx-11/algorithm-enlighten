# 模式与框架库

## 框架：算法效率选型（作者反复使用的判断框架）
拿到一个问题，作者按这个顺序判断：
1. 数据是否有序/有索引？→ 有序用二分 O(log n)；只判存在用哈希 O(1)。
2. 是否能用数据结构直接命中？→ 栈解决配对/后退，队列解决排队/BFS。
3. 是否可拆独立子问题？→ 分治（归并、快排）。
4. 是否要求枚举所有解/满足约束？→ 回溯 + 剪枝。
5. 是否求最优且子问题重叠？→ DP 填表。
6. 是否每步局部最优即可？→ 贪心（须验证贪心选择性质）。

## 决策规则：用哪种排序？
- 数据量小 / 基本有序 → 插入排序（常数小、自适应）。
- 通用大数据量 → 快速排序（缓存友好，实际最快）。
- 需要稳定 + 链表排序 → 归并排序。
- 要原地 O(n log n) → 堆排序。
- 数据量大、范围小的非负整数 → 计数/基数排序。

## 决策规则：回溯 vs DP
- 要列出所有满足约束的解（全排列、n 皇后）→ 回溯。
- 只求一个最优值（背包最大价值）→ DP。
- 子问题是否重叠：重叠 → DP；独立 → 分治。

## 反模式
1. **"递归 = 优雅高效"** —— 实际上无缓存的递归（裸斐波那契）是 O(2ⁿ) 灾难。替代：先记忆化或改递推。
2. **"O(n log n) 总比 O(n²) 快"** —— 实际上 n 很小时插入排序因常数小反而更快。替代：短区间回退插入排序。
3. **"贪心代码短就对"** —— 实际上零钱兑换在 [1,20,50] 下贪心得到 11 枚，DP 是 3 枚。替代：找反例检验贪心选择性质。
4. **"用 list.pop(0) 当队列"** —— 实际上头部删除 O(n)。替代：用 deque.popleft()。
5. **"BST 天然 O(log n)"** —— 实际上有序插入退化成斜链 O(n)。替代：AVL/红黑树平衡。
6. **"哈希查找永远 O(1)"** —— 实际上哈希函数差/负载因子高时退化成 O(n)。替代：控制负载因子、扩容重哈希。
